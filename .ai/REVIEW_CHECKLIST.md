# Review Checklist（Claude 審查 Codex 產出時逐項檢查）

> 原則：**測試綠燈 ≠ 品質過關**。Codex 的自我回報一律要親自驗證。
> Phase 0 實例：Codex 回報 slugify「全部測試通過」屬實，但 `slugify('a - b')` 輸出 `"a---b"`，
> 而它自己寫的測試剛好避開了這個 edge case。審查就是要抓這種事。

## 1. 範圍（先看，超範圍直接退回）

- [ ] `git status` / diff 中的檔案是否都在任務允許範圍內？
- [ ] 有沒有夾帶任務外的重構、風格修改、新依賴？

## 2. 正確性

- [ ] 親自執行測試（不採信回報的輸出）
- [ ] 對照任務的完成標準逐條檢查
- [ ] 手動探測至少 2 個測試沒涵蓋的 edge case（空值、邊界、特殊字元、並行）
- [ ] 錯誤路徑：失敗時的行為是否合理（不是 silent failure）？

## 3. 測試品質

- [ ] 測試是在測規格，還是在遷就實作的現狀？
- [ ] 斷言夠強嗎（strictEqual vs 只驗不丟錯）？
- [ ] 修 bug 的任務：有沒有一條測試在修復前會失敗？

## 4. 架構與維護性

- [ ] 是否違反 `.ai/ARCHITECTURE.md` 或 `.ai/DECISIONS.md` 的任何決定？
- [ ] 公開介面有沒有未經核准的變更？
- [ ] 新程式碼讀起來像不像本專案原有的程式碼？

## 5. 安全

- [ ] 有無 hardcoded 憑證、注入風險、未驗證的外部輸入？

## 結果處理

- 全部通過 → Claude 執行 commit（訊息含變更摘要）
- 有問題 → 用 `codex-reply` 帶 threadId 指出具體問題要求修正（附 file:line）
- 同一任務累計 2 次不通過 → 觸發斷路器，停止委派、重新分析
