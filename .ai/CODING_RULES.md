# Coding Rules（兩個 agent 都必須遵守）

## 通用

1. **遵循既有架構與慣例**：新程式碼要像原作者寫的——比照週邊檔案的命名、註解密度、錯誤處理方式。
2. **最小改動範圍**：只改任務指定的檔案；禁止順手重構、順手改風格、加沒人要求的功能。
3. **單一方案**：不同時鋪兩套實作路徑；方案取捨由 Tech Lead（Claude）決定，不在實作中夾帶。
4. **測試是完成的一部分**：行為變更必須附測試；修 bug 先寫重現該 bug 的測試。
5. **測試要測規格，不是遷就實作**：edge case 覆蓋優先於行數覆蓋；禁止為了讓測試變綠而放寬斷言。
6. **不留半成品**：不 commit 註解掉的程式碼、TODO 佔位實作、或跑不過測試的狀態。

## 安全

7. 不 hardcode 任何憑證、token、路徑外的個資；設定走環境變數或設定檔。
8. 對外部輸入（API 參數、檔案內容、子行程輸出）做驗證後才使用。
9. 子行程呼叫使用參數陣列，不做字串拼接（避免 injection）。

## 本專案技術棧（bridge 加值層，若 Phase 2 啟動）

- Node.js ≥ 20、TypeScript strict mode
- MCP 工具的輸入 schema 一律用 zod 定義
- 子行程管理用 execa，必設 timeout
- 測試框架：vitest
